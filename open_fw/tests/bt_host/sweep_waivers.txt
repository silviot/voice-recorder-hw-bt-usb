# Allocation-failure sweep waivers for esp_bluedroid_enable() (tests/bt_host/run_sweep.py --waivers; make test-bt-host).
#
# Every line is an UPSTREAM Bluedroid site whose allocation failure is not handled. Plan M1 "general rule" requires a
# documented patch (0011+) or an explicit waiver for each; these are the explicit waivers until the patches exist.
# A waived sweep point is reported as WAIVED and does not fail the gate; any other CRASH / HANG / CHECK does, so a new
# unhandled site (or a regression in patches 0008-0010) is caught. On target all of these end in the plan's recovery
# ladder only indirectly: an assert reboots, a hang is a stuck enable (the app's BT enable deadline must catch it).
# COUNT is the exact number of sweep points each waiver covers (stable over repeated runs). run_sweep.py fails when a
# waiver matches more points than its COUNT (a new failing path that happens to end at a waived site, e.g. a new caller
# of make_command, must not slip through) and warns when it matches fewer (fixed or stale: lower the COUNT or drop the
# line). NOT_INJECTED points (sweep-one N whose N-th attempt never happened) can never be waived.
# Found 2026-11-24 (111 allocation attempts per enable, all tasks; 61 waived points in total).
